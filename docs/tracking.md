# Трекинг людей и уходы кассира (ветка `tracking`)

Детектор людей + трекер находят, **когда** кассир ушёл и кто вошёл; Qwen спрашивается только
в эти моменты. Только рамки людей, без лиц. Отдельный модуль `pipeline/`, сервис (`app/`) не трогает.

## Что внутри

| Файл | Что делает |
|---|---|
| `pipeline/ingest.py` | кадры 5 fps, время из PTS (в роликах есть выпавшие кадры, время по индексу врёт) |
| `pipeline/tracking.py` | RT-DETR r50 (только person, порог 0,25, батчи на GPU) + ByteTrack (supervision 0.30.9); кэш `data/cache/{видео}/tracks.parquet` |
| `pipeline/events.py` | кассир, зона рабочего места от его рамки (не фиксированные координаты), шкала занятости, события `departure` / `return` / `intrusion` / `entry`; `events.json` |
| `config/tracking.yaml` | все пороги; общие для всех роликов, под отдельные ролики не подгонялись |
| `scripts/viz_tracks.py` | debug-видео: рамки с ID, зона, полоса занятости, события |
| `scripts/eval_departures.py` | события против разметки |
| `scripts/eval_tracking_vlm.py` | связка: на каждом уходе 4 вопроса Qwen по кропу стола |
| `tests/test_events.py` | сглаживание и поиск уходов на синтетических шкалах |

## Цифры (42 ролика датасета, Qwen3-VL-30B, 18.10)

**Детектор:** кассира видит на всех проверенных кадрах (0,85–0,98), в том числе в наклоне.
Ложные рамки — люди за стеклом и отражения (0,3–0,67): отсекаются средним score трека ≥ 0,5.
Скорость на V100 ~50 мс/кадр — ролик 145 с за ~35 с.

**Связка трекинг → Qwen** (на уходе кадры +1 и +2 с: деньги, сейф, рабочие вещи, экран; «да» на обоих):

| | Найдено | Ложных | Верный вердикт |
|---|---|---|---|
| трекинг → Qwen (только «ушёл и оставил») | 4/22: Х-11, Х-24, Х-26, Х-28 | **0/20** | 24/42 |
| пайплайн main (run_review.md) | 20/22 | 8/20 | 32/42 |

Ни одного ложного на 7 чистых роликах, где кассир уходит правильно (Х-12, 14, 23, 25, 27, 29, 31).
**Х-24 — пропуск main** («рабочие вещи»), здесь пойман.

1. **Объединение «сработал любой»**: + Х-24 без новых ложных → ожидаю 33/42.
2. **Экран только на уходе по трекингу** вместо «кассира нет за столом»: Х-11 и Х-28 трекинг

## Ограничения

- Таймкод ухода позже метки на 0,4–9 с: разметка ставит момент действия (оставила деньги),
  трекинг — момент выхода из зоны. Где сработали оба, брать таймкод main.
- Ключ в замке не виден (4 px). Х-15 обрезан через 0,8 с после ухода — ухода нет.
- `entry` (вошёл другой человек) неспецифичен: клиенты входят и в чистых роликах. Кандидат, не вердикт.
- Сценарии с клиентом (документ, пересчёт, УФ) трекинг не решает.

## Запуск

```bash
pip install -r requirements-tracking.txt
python scripts/eval_departures.py                      # треки + события по всем роликам (нужен GPU)
python scripts/viz_tracks.py X-26                      # debug-видео в data/debug/
python scripts/eval_tracking_vlm.py --base-url http://127.0.0.1:8080/v1   # связка с Qwen
```
На Shabyt всё уже стоит в `~/dalel/track/` (venv, код, кэш треков); GPU — внутри задачи сервера
модели: `srun --jobid=<id> --overlap ...`, модель с login-узла доступна по `http://gn04:8080/v1`.
