# API для фронтенда

Все пути ниже указаны относительно адреса FastAPI. Идентификаторы `video_id` и
`job_id` — UUID. Видео загружается как `multipart/form-data`, поле `file`.

## Доступ

Есть два набора маршрутов:

- `/ui/*` — текущий браузерный сценарий без ключа, если `UI_OPEN=1` (по умолчанию).
- `/api/v1/*` — каталог и API жюри с заголовком `X-API-Key`.

**Не помещайте `API_KEY` в JavaScript, HTML или публичную сборку фронтенда.**
Для браузерного каталога сохранённых видео понадобится авторизация с cookie или
серверный прокси, который добавляет ключ. Сейчас без ключа доступны только загрузка
и статус конкретного задания через `/ui/*`; список всей истории защищён ключом.
Фронт и API лучше размещать на одном origin: CORS отдельно не настроен.

## Основной сценарий браузера

### 1. Загрузить видео

`POST /ui/analyze` — `FormData` с полем `file`; поддерживаются `.mov`, `.mp4`, `.m4v`.
Лимит по умолчанию — 200 МБ. Сервис сохраняет файл и сразу ставит анализ в очередь.

```json
{
  "video_id": "5ae0207f-a48f-42dd-82f7-c14b2573586f",
  "job_id": "7ea53d6f-b237-4fc7-95da-f075f4037f59",
  "status": "processing"
}
```

Сохраните оба ID в состоянии фронта. Для возвращения к ролику в том же браузере
можно сохранять `job_id` в `localStorage` до появления серверной авторизации.

### 2. Получать статус

`GET /ui/jobs/{job_id}`. Пока анализ идёт, опрашивайте маршрут примерно раз в
1–2 секунды. Очередь также отображается как `processing`.

```json
{
  "job_id": "7ea53d6f-b237-4fc7-95da-f075f4037f59",
  "status": "processing",
  "stage": "Анализ кадров",
  "progress": 0.42,
  "video_id": "5ae0207f-a48f-42dd-82f7-c14b2573586f",
  "stream_url": "/api/v1/videos/5ae0207f-a48f-42dd-82f7-c14b2573586f/stream?expires=...&signature=..."
}
```

`progress` — число от 0 до 1. Если статус `failed`, ответ содержит `error`.
После завершения ответ содержит `status: "done"`, `verdict` (`violation` или
`no_violation`) и массив `violations`:

```json
{
  "job_id": "7ea53d6f-b237-4fc7-95da-f075f4037f59",
  "status": "done",
  "verdict": "violation",
  "violations": [
    {
      "type": "Название события",
      "timecode_sec": 44.2,
      "description": "Что видно на записи и почему это требует проверки",
      "evidence_frames": [
        {"timestamp_sec": 44.2, "image_base64": "/9j/4AAQ..."}
      ],
      "rule": {"document": "Название документа", "section": "Пункт", "url": "https://..."}
    }
  ],
  "video_id": "5ae0207f-a48f-42dd-82f7-c14b2573586f",
  "stream_url": "/api/v1/videos/5ae0207f-a48f-42dd-82f7-c14b2573586f/stream?expires=...&signature=..."
}
```

`rule` появляется только при наличии проверенного нормативного источника.
Если событий нет, `violations` — пустой массив. Для панели справа используйте
`violations` как список значимых событий; для кадра-доказательства задайте
`src="data:image/jpeg;base64,..."`.

### 3. Плеер и переход по событию

Установите `stream_url` в `src` элемента `<video>`. Подписанная ссылка действует
один час. После истечения срока снова запросите `/ui/jobs/{job_id}` и возьмите
новую ссылку. Плеер может запрашивать диапазоны байтов (`Range`); сервер отдаёт
`206 Partial Content` для перемотки.

```js
video.src = job.stream_url;
function jumpTo(event) {
  video.currentTime = event.timecode_sec;
  video.play();
}
```

Файл отдается в исходном формате. Если кодек внутри `.mov` не поддерживается
браузером, потребуется отдельная версия видео для просмотра.

## Каталог и расширенные данные

Следующие маршруты требуют `X-API-Key` и предназначены для доверенного клиента
или серверного прокси фронтенда.

| Метод | Путь | Что возвращает |
|---|---|---|
| `POST` | `/api/v1/videos` | Загрузка и запуск анализа; `202`, `video_id`, `job_id`, `status` |
| `GET` | `/api/v1/videos?limit=100&offset=0` | `items`: список видео, максимум 100 за запрос |
| `GET` | `/api/v1/videos/{video_id}` | Метаданные одного видео |
| `GET` | `/api/v1/videos/{video_id}/events` | Значимые события последнего успешного анализа |
| `GET` | `/api/v1/videos/{video_id}/frames` | JSON ответов модели по выбранным кадрам |
| `POST` | `/api/v1/videos/{video_id}/analyze` | ID существующего анализа; `?force=true` запускает новый |
| `GET` | `/api/v1/jobs/{job_id}` | Статус и результат в формате API жюри |

### Работники и их видео

Эти маршруты требуют `X-API-Key`. В текущем React-фронте список сотрудников и
назначения пока локальные; UUID из этих маршрутов к нему ещё не подключены.

1. `POST /api/v1/new-worker` с JSON `{"name":"Аида Садыкова"}` создаёт работника.
   Ответ `201`:

   ```json
   {"worker_id":"0fdc4dfb-ef71-473e-958b-68efc6addf70","name":"Аида Садыкова","created_at":"2026-10-17T13:00:00+00:00"}
   ```

2. `POST /api/v1/workers/{worker_id}/videos` принимает `multipart/form-data`, поле
   `file`, сохраняет привязку и запускает анализ. Ответ `202` содержит
   `video_id`, `job_id`, `status`, `worker_id`.
3. `GET /api/v1/workers/{worker_id}/videos?limit=100&offset=0` возвращает
   `{"worker_id":"...","items":[...]}`. У каждого видео есть `worker_id`.
   Список пуст, если работник существует, но записей нет. Неизвестный UUID — `404`.

Обычные загрузки через `/api/v1/videos`, `/api/v1/analyze` и `/ui/analyze` остаются
без привязки (`worker_id: null`). `worker_id` в метаданных и общем списке видео
тоже может быть `null` для старых записей.

`GET /api/v1/videos/{video_id}` и элементы списка имеют форму:

```json
{
  "video_id": "5ae0207f-a48f-42dd-82f7-c14b2573586f",
  "worker_id": null,
  "original_name": "video_017.mov",
  "size_bytes": 29360128,
  "duration_sec": 68.4,
  "created_at": "2026-10-17T13:00:00+00:00",
  "job_id": "7ea53d6f-b237-4fc7-95da-f075f4037f59",
  "latest_completed_job_id": "7ea53d6f-b237-4fc7-95da-f075f4037f59",
  "analysis_status": "done",
  "stream_url": "/api/v1/videos/5ae0207f-a48f-42dd-82f7-c14b2573586f/stream?expires=...&signature=..."
}
```

`analysis_status` может быть `queued`, `processing`, `done` или `failed`.
`job_id` и `latest_completed_job_id` могут быть `null`. При повторном анализе
старый готовый результат доступен через `latest_completed_job_id`.

`GET /api/v1/videos/{video_id}/events` возвращает `video_id`, `job_id` и
`events`. Каждый элемент содержит `event_index`, `timecode_sec`, `type`,
`description`, `rule` (или `null`) и `evidence_frames`. Для выбора конкретного
анализа можно передать `?run_id={job_id}`. Аналогично работает `/frames`:
элементы массива `frames` содержат `frame_index`, `timestamp_sec` и `analysis`
с полями `answers` и `reasons`. Это результаты **выбранных для анализа кадров**,
а не всех кадров исходного видео.

`POST /api/v1/videos/{video_id}/analyze` без `force=true` возвращает текущий
или последний готовый `job_id` и не вызывает модель повторно. `force=true`
создаёт новый анализ, если сейчас нет задания в очереди или обработке.

## Выдача исходного видео

`GET /api/v1/videos/{video_id}/stream` принимает либо `X-API-Key`, либо
параметры `expires` и `signature` из `stream_url`. Для обычного `<video>`
используйте подписанную ссылку: элемент не умеет добавлять заголовок API-ключа.

## API жюри

`POST /api/v1/analyze` принимает `.mov` в поле `file` и возвращает только
`job_id` и `status`. `GET /api/v1/jobs/{job_id}` отдаёт `processing`, `done`
или `failed`; при `done` — вердикт и нарушения в формате ТЗ. Оба маршрута
требуют `X-API-Key`.

## Ошибки

| HTTP | Причина |
|---|---|
| `400` | Неподдерживаемый или не читаемый видеофайл |
| `401` | Неверный или отсутствующий ключ; недействительная ссылка на видео |
| `404` | Видео, задание или работник не найден |
| `413` | Файл превышает `MAX_UPLOAD_MB` |
| `422` | Некорректный UUID или параметр запроса |

При недоступной БД запрос может завершиться серверной ошибкой; перед повторной
загрузкой проверьте, не появилось ли видео в каталоге, чтобы не создать копию.
