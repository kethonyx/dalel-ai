# Контроль кассовой дисциплины по видео (Datathon 26)

Сервис: веб-интерфейс + API для жюри, PostgreSQL-каталог видео и результатов,
один воркер, пайплайн с подключаемой локальной моделью. **По умолчанию модель не подключена**: сервис работает на заглушке и всегда
отвечает «Нарушение не обнаружено» (кроме режима `STUB_DEMO=1`, где выдаётся одно
помеченное «ДЕМО» событие для проверки интерфейса).

## Запуск

Нужны Python 3.10+, Docker Compose и `ffmpeg`/`ffprobe` в PATH.

```bash
docker compose up -d --wait db
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt

export API_KEY="придумайте-длинный-ключ"            # Windows: set API_KEY=...
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Compose поднимает PostgreSQL на `127.0.0.1:5433`, создаёт базу `dalel` и выполняет
единственный скрипт [db/init.sql](db/init.sql). Данные PostgreSQL остаются в Docker volume,
исходные видео — в `data/videos/`. Пароль `dalel_dev_password` предназначен только для
локальной разработки; при другом `POSTGRES_PASSWORD` задайте соответствующий
`DATABASE_URL=postgresql://dalel:<пароль>@127.0.0.1:5433/dalel` для приложения.
Скрипт инициализации выполняется **только при первом запуске с пустым volume**;
изменения схемы существующей базы нужно применять отдельно.

Интерфейс: http://127.0.0.1:8000 . Проверка API (как у жюри):

```bash
curl -X POST http://127.0.0.1:8000/api/v1/analyze -H "X-API-Key: $API_KEY" -F "file=@video_017.mov"
# -> {"job_id":"3f2a9c1e","status":"processing"}
curl http://127.0.0.1:8000/api/v1/jobs/3f2a9c1e -H "X-API-Key: $API_KEY"
```

Без верного ключа API отвечает `401`. Интерфейс использует отдельные маршруты `/ui/*`
без ключа (`UI_OPEN=0` отключает их). Запускайте один процесс Uvicorn:
внутри него работает один воркер анализа, остальные видео ждут в очереди.

## Сохранённые видео и временная шкала

Контракт для фронтенда и примеры ответов: [docs/frontend_api.md](docs/frontend_api.md).

Каждая загрузка создаёт запись видео и запуск анализа. Результат, ответы модели для
проанализированных кадров и найденные события сохраняются в PostgreSQL. Повторное
открытие видео не вызывает модель. Дополнительные маршруты с `X-API-Key`:

| Метод | Путь | Результат |
|---|---|---|
| `POST` | `/api/v1/videos` | загрузить и поставить видео в очередь; `video_id`, `job_id` |
| `GET` | `/api/v1/videos` | список сохранённых видео |
| `GET` | `/api/v1/videos/{video_id}` | метаданные, статус, временная ссылка для плеера |
| `GET` | `/api/v1/videos/{video_id}/events` | значимые события с таймкодами и описаниями |
| `GET` | `/api/v1/videos/{video_id}/frames` | JSON ответов модели для выбранных кадров |
| `POST` | `/api/v1/videos/{video_id}/analyze` | вернуть существующий результат; `?force=true` запускает повторный анализ |
| `GET` | `/api/v1/videos/{video_id}/stream` | исходный файл; `Range` для перемотки |

`stream` принимает `X-API-Key` либо подписанную ссылку из метаданных видео
(срок действия — один час). Доступность `.mov` в браузере зависит от кодека;
API отдаёт исходный файл без перекодирования. История хранится, пока видео и записи
не удалены администратором. Веб-интерфейс пока показывает только последний загруженный
ролик; экран каталога и плеер можно подключить к этим маршрутам отдельно.

## Подключение модели (локально)

Модель крутится отдельным локальным сервером с OpenAI-совместимым API, сервис ходит к ней
по `VLM_BASE_URL`. **Адрес обязан быть локальным** (loopback или частная сеть), иначе
сервис откажется отправлять кадры: облачные AI-сервисы запрещены, за них дисквалификация.

```bash
brew install ffmpeg llama.cpp
# Qwen2.5-VL-3B Q4_K_M + mmproj (~3 ГБ, скачается один раз в ~/.cache/huggingface), влезает в M1 8 ГБ
llama-server -hf ggml-org/Qwen2.5-VL-3B-Instruct-GGUF:Q4_K_M --host 127.0.0.1 --port 8080 -ngl 99 -c 4096

export VLM_BACKEND=openai_local
export VLM_BASE_URL=http://127.0.0.1:8080/v1
```

Весь код модели спрятан за `app/vlm.py::ask(image, question)`: другая модель или другой
сервер это другой бэкенд, остальное не меняется.

## Как добавлять нарушения

1. Просмотрите ролики, определите типы нарушений и таймкоды.
2. Для каждого типа найдите норму (adilet.zan.kz, акты НБРК), **проверьте пункт вручную**.
3. Добавьте правило в `rules.json`: узкий вопрос «да/нет» к кадру, формулировка наблюдения
   без домыслов, источник. Пока `source.verified = false`, в описании будет
   «норматив уточняется» и ссылки не будет: так сделано специально (критерий 4).
4. Включите правило (`"enabled": true`), прогоните `scripts/run_dir.py` на папке роликов,
   подберите `min_consecutive` и формулировку вопроса так, чтобы не было пропусков.

Сейчас в `rules.json` два выключенных примера-гипотезы.

## Параметры (переменные окружения)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `API_KEY` | случайный при старте | ключ для заголовка `X-API-Key` |
| `DATABASE_URL` | `postgresql://dalel:dalel_dev_password@127.0.0.1:5433/dalel` | подключение к PostgreSQL |
| `VLM_BACKEND` | `stub` | `stub` или `openai_local` |
| `VLM_BASE_URL` / `VLM_MODEL` | `http://127.0.0.1:8080/v1` / `local` | локальный сервер модели |
| `FRAME_FPS` | `1` | максимум кадров в секунду для анализа |
| `MAX_FRAMES` | `40` | максимум анализируемых кадров на видео |
| `FRAME_MAX_SIDE` | `640` | размер кадра для модели |
| `TIME_BUDGET_SEC` | `270` | после этого анализ останавливается и отдаёт найденное |
| `MAX_UPLOAD_MB` | `200` | лимит загрузки |
| `STUB_DEMO` | `0` | `1`: помеченное тестовое событие для проверки интерфейса |

Если модель работает на отдельном сервере команды, можно поднять SSH туннель
до её OpenAI-совместимого HTTP API и указать локальный конец в `VLM_BASE_URL`.
Сервис передаёт модели выбранные JPEG-кадры, исходное видео остаётся в `data/videos/`.
Туннель должен работать до запуска обработки и не создаётся каждым HTTP-запросом.
Например, если модель слушает `127.0.0.1:8080` на GPU-сервере:

```bash
ssh -N -L 127.0.0.1:8080:127.0.0.1:8080 user@gpu-server
export VLM_BACKEND=openai_local
export VLM_BASE_URL=http://127.0.0.1:8080/v1
```

## Публичный URL

Cloudflare Tunnel подходит (это только сетевой туннель, не AI-сервис):
`cloudflared tunnel --url http://127.0.0.1:8000`. Отключите сон компьютера и
автообновления на время проверки жюри.

  `MAX_VLM_CALLS`). Детектор должен выдавать кандидатные кадры.
- Таймкод события = время первого кадра серии «yes», точность ±1/`FRAME_FPS` с.
- Кадры-доказательства вырезаются из оригинала видео в точный момент времени.
- Не проверялось под другим ракурсом камеры.
