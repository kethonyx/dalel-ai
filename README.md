# Контроль кассовой дисциплины по видео (Datathon 26)

Скелет сервиса: веб-интерфейс + API для жюри, один воркер, пайплайн с подключаемой
локальной моделью. **Сейчас модель не подключена**: сервис работает на заглушке и всегда
отвечает «Нарушение не обнаружено» (кроме режима `STUB_DEMO=1`, где выдаётся одно
помеченное «ДЕМО» событие для проверки интерфейса).

## Запуск

Нужны Python 3.10+ и `ffmpeg`/`ffprobe` в PATH.

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt

export API_KEY="придумайте-длинный-ключ"            # Windows: set API_KEY=...
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Интерфейс: http://127.0.0.1:8000 . Проверка API (как у жюри):

```bash
curl -X POST http://127.0.0.1:8000/api/v1/analyze -H "X-API-Key: $API_KEY" -F "file=@video_017.mov"
# -> {"job_id":"3f2a9c1e","status":"processing"}
curl http://127.0.0.1:8000/api/v1/jobs/3f2a9c1e -H "X-API-Key: $API_KEY"
```

Без верного ключа API отвечает `401`. Интерфейс использует отдельные маршруты `/ui/*`
без ключа (`UI_OPEN=0` отключает их). Одно видео за раз: остальные ждут в очереди.

## Подключение модели (локально)

Модель крутится отдельным локальным сервером с OpenAI-совместимым API, сервис ходит к ней
по `VLM_BASE_URL`. **Адрес обязан быть локальным** (loopback или частная сеть), иначе
сервис откажется отправлять кадры: облачные AI-сервисы запрещены, за них дисквалификация.

```bash
brew install ffmpeg llama.cpp
# Qwen2.5-VL-3B Q4_K_M + mmproj (~3 ГБ, скачается один раз в ~/.cache/huggingface), влезает в M1 8 ГБ
llama-server -hf ggml-org/Qwen2.5-VL-3B-Instruct-GGUF:Q4_K_M --host 127.0.0.1 --port 8080 -ngl 99 -c 4096

export VLM_BACKEND=openai_local
export VLM_BASE_URL=http://127.0.0.1:8080/v1
```

Весь код модели спрятан за `app/vlm.py::ask(image, question)`: другая модель или другой
сервер это другой бэкенд, остальное не меняется.

## Как добавлять нарушения

1. Просмотрите ролики, определите типы нарушений и таймкоды.
2. Для каждого типа найдите норму (adilet.zan.kz, акты НБРК), **проверьте пункт вручную**.
3. Добавьте правило в `rules.json`: узкий вопрос «да/нет» к кадру, формулировка наблюдения
   без домыслов, источник. Пока `source.verified = false`, в описании будет
   «норматив уточняется» и ссылки не будет: так сделано специально (критерий 4).
4. Включите правило (`"enabled": true`), прогоните `scripts/run_dir.py` на папке роликов,
   подберите `min_consecutive` и формулировку вопроса так, чтобы не было пропусков.

Сейчас в `rules.json` два выключенных примера-гипотезы.

## Параметры (переменные окружения)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `API_KEY` | случайный при старте | ключ для заголовка `X-API-Key` |
| `VLM_BACKEND` | `stub` | `stub` или `openai_local` |
| `VLM_BASE_URL` / `VLM_MODEL` | `http://127.0.0.1:8080/v1` / `local` | локальный сервер модели |
| `FRAME_FPS` | `2` | кадров в секунду для анализа |
| `FRAME_MAX_SIDE` | `640` | размер кадра для модели |
| `MAX_VLM_CALLS` | `120` | потолок вызовов модели на видео |
| `TIME_BUDGET_SEC` | `270` | после этого анализ останавливается и отдаёт найденное |
| `MAX_UPLOAD_MB` | `200` | лимит загрузки |
| `STUB_DEMO` | `0` | `1`: помеченное тестовое событие для проверки интерфейса |

## Публичный URL

Cloudflare Tunnel подходит (это только сетевой туннель, не AI-сервис):
`cloudflared tunnel --url http://127.0.0.1:8000`. Отключите сон компьютера и
автообновления на время проверки жюри.
